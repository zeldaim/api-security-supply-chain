### 게이트 실패 — 고치지 않고 그대로 기록

`[GATE] ❌ 실패 — 조용한 정상 창 49개 < 50 · 오탐률 4.1% > 2%`

- **창 수 49 < 50:** 검증용(뒤 15%) 80창 중 학습 기간과 겹치는 30창을 빼서 49창. 데이터 양 문제(한 창 모자람).
- **오탐 2/49:** 둘 다 **수집이 끝나는 마지막 5분 창**(window_start 1794991800)에서 요청 5건이 같은 초에 몰린 창이다(`gap_mean_log 0`). 생성기가 멈추면서 잘린 창이지만, 실제 사용자가 짧게 몰아서 쓰고 나가도 같은 모양이므로 오탐으로 센다.
- medium+ 는 검증 창의 39% — medium 기준(0.071)이 느슨하다. 운영 판단은 high 기준으로 한다.
- 게이트 기준(창 50 · 오탐 2%)을 낮춰서 통과시키지 않았다.

## 한계

- **정상 트래픽이 기계가 만든 것이다.** 30명이 1초 간격으로 돌아가며 2~4건씩 요청한다. 사람 속도의 정상(crAPI 3차에서 공개 데이터 재생으로 확인한 문제)은 이번에 보지 않았다 — crAPI 에서는 규칙 정상만으로 학습한 모델이 재생 정상을 거의 전부 오탐했다.
- **1 IP = 1 사람, 공격 IP 는 공격만 한다.** 실제보다 쉬운 조건이다. IP 는 창을 나누는 데와 채점(정답지)에만 쓰고 특징에는 없다(`--no-ip`).
- 공격은 같은 생성기로 1회씩이다(1차와 특징값이 같다).

## 따라 하기

준비: DVRA 기동과 nginx 앞단은 [`../rules_2026-11-18/README.md`](../rules_2026-11-18/README.md) "다시 돌리기"와 같다(로그 경로만 이 폴더의 `work/logs`). `e2e-runner` 이미지 필요.

```bash
cd /d/api-security-supply-chain/verify/dvra/ml_run2_2026-11-18
python dvra_traffic_relogin.py --users 30 --rounds 130 --pause 1.0     # 약 73분. 예상 마지막 줄: 재로그인 60회

#  예상: 학습 창 365 · 스캐너 0 / [GATE] ❌ 실패 (49 < 50 · 4.1%) / BOLA high · probe medium
```
