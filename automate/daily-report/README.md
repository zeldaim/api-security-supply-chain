# 일일 자동 보안 보고서

매일 수집(SBOM · API-BOM · 판정)이 끝나면 **레포 안 결과만 읽어** 보안 일일 보고서를 만든다. 사람이 쓰지 않는다.

- 생성기: [`daily_report.py`](daily_report.py) — 표준 라이브러리만 사용
- 샘플 보고서: [`sample/2026-11-09_0843_보안일일보고서.md`](sample/2026-11-09_0843_보안일일보고서.md) (팀 쇼핑몰 대상, 2026-11-09 실제 생성본)

## 보고서에 들어가는 것

| 절 | 내용 |
|---|---|
| 요약 | 기준 위반(높음/중간), 직전 보고 대비 **신규 · 해소**, 부품 취약점 건수(Dependency-Track), **가장 위험한 API 와 점수 근거**, 근본 원인(지원 종료 OS · 런타임), 사람이 결정할 것 |
| 보안 발견사항 | 자동 판정 결과를 ID 로 정리 (부품 취약점 S1~S3, API · 자산 기준 G1~G9) |
| 근거 | 각 항목마다 판정 근거 (명세에 없음, 구버전 API, 실증된 취약점, 외부 노출 등) |

## 동작 방식

- 입력은 전부 레포 안 파일이다: 판정 CSV, 예외 목록, 위험 순위, Dependency-Track 이력, 인벤토리 실행 로그, 승인 기록.
- **실행마다 새 파일**로 쌓고 덮어쓰지 않는다. 같이 남기는 `*.state.json` 으로 다음 보고에서 신규 · 해소를 비교한다.
- 사람이 판단해야 하는 것(예외 없는 위반을 고칠지, 예외 승인할지)은 요약의 "사람 결정 필요"에 따로 올린다.

## 샘플 보고서에서 읽을 수 있는 것 (2026-11-09 08:43)

- 기준 위반 높음 37 · 중간 22, 부품 취약점 2,355건(Critical 189).
- 가장 위험한 API: `GET /api/v1/users/{id}` — 명세에 없고(shadow), 개인정보를 다루고, 실증된 BOLA 가 있고, 연결된 부품에 Critical 이 있다.
- 근본 원인: Debian 11 지원 종료(2026-08-31), PHP 7.4 지원 종료(2022-11-28).

## 실습 서버가 꺼진 날 — 오프라인 자동화

실습 서버(VM)는 평일 낮에만 켜져 있었다. 꺼진 날도 보고서가 끊기지 않게, 그리고 **꺼진 서버를 스캔해서 인벤토리가 오염되는 것**을 막으려고 오프라인 모드를 따로 만들었다.

| 파일 | 역할 |
|---|---|
| [`offline/daily-offline.yml`](offline/daily-offline.yml) | GitHub Actions. 매일 10:35 KST 에 `OFFLINE=1` 로 실행 (서버가 살아 있어 이미 커밋돼 있으면 중복 없이 넘어감). 수동 실행도 가능 |
| [`offline/daily.sh`](offline/daily.sh) | 매일 작업 전체(로그 수집 → 관측 → 스캔 → 합치기 → 새 후보 → Dependency-Track → 보고서). `OFFLINE=1` 이면 서버가 필요한 단계를 건너뛰고, `OFFLINE=auto` 면 서버 포트가 닫혀 있을 때 스스로 오프라인으로 바꾼다 |
| [`offline/routine.sh`](offline/routine.sh) | 사람이 직접 돌리는 한 줄 루틴 (`check` · `sbom` · `daily` · `report` · `all` · `dash`). 서버가 꺼져 있으면 자동으로 오프라인 |

| 단계 | 서버 켜짐 | 서버 꺼짐 (오프라인) |
|---|---|---|
| ① 웹 로그 SSH 수집 | 실행 | **건너뜀** |
| ③ 블랙박스 스캔 | 실행 | **건너뜀** (직전 결과를 유지) |
| ④ 인벤토리 합치기 · ⑤ 새 후보 계산 | 실행 | 실행 |
| ⑥ · ⑦ Dependency-Track 업로드 · 대시보드 | 실행 | **건너뜀** |
| ⑧ 자동 보안 일일 보고서 | 실행 | 실행 |

- 이유: 2026-11-06 에 서버가 꺼진 채로 스캔을 돌렸더니 모든 서비스가 "filtered" 로 기록돼 인벤토리가 오염됐다. 그래서 2026-11-07 에 오프라인 모드를 추가했다.
- 한계: 오프라인 날에는 로그 수집과 스캔이 없으므로 그날의 새 트래픽·새 열린 포트는 보고서에 반영되지 않는다. 서버가 다시 켜진 날 따라잡는다.

## 한계

- 입력 경로는 원본 저장소 구조 기준이라 이 폴더만으로는 실행되지 않는다(`policy/`, `graph/`, `dt_history/` 등이 필요).
- 대상 환경(팀 쇼핑몰, Dependency-Track)은 교육과정 종료로 더 이상 없다. 샘플은 그 실행의 기록이다.
